# Array OTP 注册

本文说明 Array Networks OTP 的参数发现、密钥注册、时间同步及桌面端集成。验证码使用 HMAC-SHA-1，输出 6 位数字，生成周期由网关提供；认证时将验证码追加到静态密码末尾。

重新注册会覆盖网关中已有的 OTP 密钥，使用旧密钥的验证器可能无法继续认证。调用注册接口前，必须向用户明确提示并取得确认。

## 接口顺序

所有请求复用同一 Cookie 容器、相同网关源及现有 TLS/代理配置，User-Agent 固定为 `MotionProOTP/108`。

1. GET `/prx/000/http/localhost/an_login.js`，读取 `_AN_dyncode_interval`，限定 1–300 秒。
2. GET `/prx/000/http/localhost/register`，确认页面声明 `otp_reg`。
3. POST 同一注册路径，URL 编码提交 `method=otp_reg`、`uname`、静态 `pwd` 和本机生成的 16 字符 BASE32 `sm`；不附加认证组或验证码。
4. POST 必须返回 302 到同源的 `/prx/000/http/localhost/login`。保留 Location 的查询参数，再读取登录页；非空 `_AN_str_errormsg_login` 视为拒绝，不把服务器错误正文写入日志。
5. GET `/prx/000/http/localhost/system-time`，读取 `<time>` 秒级时间戳，以请求往返中点估算钟差。

普通页面只跟随同源 HTTPS 重定向。HTTP 页面支持 Content-Length、chunked（含分片/尾部）及连接关闭定界，正文限制 1 MiB。注册 POST 不自动跟随重定向，不读取或记录密码/种子回显。

网关已确认注册后，校时失败仍返回注册成功并标记未同步，使用本机时间且记录警告。此时不把远程已生效的注册当作失败而丢弃新种子。

## Rust API

`VpnClient::otp_parameters()` 无需密码，可发现周期和钟差。`VpnClient::enroll_otp(SecretString)` 使用配置中的用户名及静态密码，也支持 TLS 验证之后的 `PasswordProvider`。两者无需管理员权限或 TUN，可通过 `client.handle().disconnect()` 取消。

调用方必须先取得覆盖确认、持久保存候选种子，再调用注册接口。收到 `VpnError::OtpEnrollmentUncertain` 时，远程可能已生效，必须保留候选，不能简单恢复成只有旧密钥的状态。

桌面端在系统密钥库中分别保留当前种子和待确认候选，SQLite 只保存状态、周期和钟差。注册成功后先提交当前密钥与参数，再移除候选；本地事务失败保留候选以便恢复。取消不会向网关发送撤销操作。

## 界面行为

- 手动填写密钥：填写后自动生成验证码；不设置密钥时，连接及重新认证请求手动输入 6 位验证码。编辑已有密钥时留空保留，使用「移除本地密钥」按钮切换为手动输入验证码。
- 自动注册：先保存当前配置，再输入或使用已保存的静态密码。明确确认覆盖后才生成候选并请求注册。重试未确认的注册复用同一候选。
- 扫码导出：显式点击后生成标准 URI 的 SVG 二维码，包含账号、网关标识、SHA-1、6 位及网关周期；不包含静态密码。目标验证器需支持该周期，其他 App 不会获得本客户端单独保存的网关钟差，需保持系统时间正确。

## 测试与兼容性

`tests/otp_enrollment.rs` 使用本地 Rustls 模拟网关验证请求顺序、特殊字符编码、Cookie 更新、完整重定向目标、HTTP 分片及关闭定界、周期和钟差、错误密码、跨源拒绝、POST 后断线、无效证书、非法长度、取消与校时失败。

桌面测试覆盖 RFC 6238 的 SHA-1 向量、二维码 URI、旧配置迁移及注册后本地密钥库/数据库失败时的候选保留。自动化测试使用模拟凭据和模拟网关。

不同网关固件的注册接口及页面格式可能存在差异，部署前应在目标设备上验证注册、认证、时间同步与异常恢复。第三方 TOTP App 还需支持网关提供的生成周期。模拟测试通过不代表所有网关或验证器均已通过兼容性验证。
